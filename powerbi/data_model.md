# Data model — star schema

All data is **synthetic** (generated by `data/generate_data.py`).

## Fact tables

| Table | Grain | Key measures |
|---|---|---|
| `order_items` | one row per order line | `quantity`, `unit_price`, `discount` → revenue = qty × price × (1 − discount) |
| `returns` | one row per returned line item | return counts, return reasons |

## Dimension tables

| Table | Key | Attributes |
|---|---|---|
| `orders` | `order_id` | `order_date`, `status`, `payment_method`, `customer_id` |
| `customers` | `customer_id` | `name`, `city`, `signup_date`, `segment` |
| `products` | `product_id` | `name`, `category`, `price`, `cost` |

## Relationships (all single-direction, one-to-many)

```
customers (1) ──< orders (many)        on customer_id
orders    (1) ──< order_items (many)   on order_id
products  (1) ──< order_items (many)   on product_id
orders    (1) ──< returns (many)       on order_id   (inactive by default;
products  (1) ──< returns (many)       on product_id  activate with USERELATIONSHIP when needed)
Date      (1) ──< orders (many)        on order_date  (see below)
```

## Date table

Create a calculated Date table in Power BI (Modeling → New table):

```dax
Date =
ADDCOLUMNS (
    CALENDAR ( DATE ( 2023, 1, 1 ), DATE ( 2024, 12, 31 ) ),
    "Year", YEAR ( [Date] ),
    "Month", FORMAT ( [Date], "yyyy-mm" ),
    "MonthName", FORMAT ( [Date], "mmm yyyy" ),
    "Quarter", "Q" & FORMAT ( [Date], "q" )
)
```

Mark it as the date table, then join `Date[Date]` → `orders[order_date]`
(single direction). This powers the time-intelligence measures in
`dax_measures.dax` (MoM growth, YTD, YoY).

## Notes

- `order_items` has a composite key (`order_id`, `product_id`); Power BI does
  not need a surrogate key for this model.
- Hide the `returns` bridge's inactive relationships to avoid ambiguity;
  use `USERELATIONSHIP` inside return-specific measures if you activate them.
- Cardinality is small (~12k fact rows), so Import mode is fine.
